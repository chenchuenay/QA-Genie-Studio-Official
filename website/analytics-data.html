Analytics Data

Last updated: June 28, 2026

This page describes exactly what data QA Genie collects when you opt in to anonymous usage analytics. This data helps improve the app experience, fix bugs, and prioritise features.

1. Analytics Events (Firebase Analytics)

When analytics consent is granted, the following events are logged:

  • App opens — when you launch the app
  • Screen views — which screens you visit (e.g. Home, Suites, Account, Suite Preview)
  • Generation events — started, completed, or failed generations with metadata (platform, mode, count, duration, reason)
  • Exports — when you export test cases, with format and count
  • Rewarded ad completions — when you watch an ad, with placement info
  • Upgrade intent — if you show interest in the PRO tier
  • Bug reports — when you submit an issue report, with category
  • Debug auth events — anonymous auth flow diagnostics (no personal identifiers)

No test case content, module names, feature names, or prompt text is ever included in analytics events. Only metadata counts and timestamps.

2. Firestore Data (Signed-In Users)

When you sign in with Google, the following data is stored in Firestore to enable cross-device sync and quota management:

  • Email address — from your Google account
  • Display name — from your Google account
  • User ID — Firebase Authentication UID
  • Suite metadata — module names, feature names, creation/update timestamps (not test case content)
  • Usage counts — number of generations and exports per day
  • Device ID — for session management and quota enforcement
  • Ad reward tokens — cryptographically random tokens to prevent reward abuse

3. Cloud Storage (Signed-In Users)

Your full test case content is stored in Google Cloud Storage (GCS) to enable cross-device sync. This includes:

  • Test case IDs, titles, descriptions
  • Preconditions and test steps
  • Expected results
  • Test data

This data is encrypted in transit and at rest. It is never used for training, analysis, or sharing with any third party beyond the cloud infrastructure required to operate the sync feature.

4. Guest Accounts (Anonymous)

Guest accounts use only:

  • Firebase Installation ID — for quota tracking and device identity
  • Device-based usage counters — stored in a server collection keyed by device ID

Guest accounts are local-only. No test case content ever leaves your device.

5. Device Information

Device model, app version, and platform (Android) are collected only when you submit an issue report voluntarily.

6. Third-Party Services

QA Genie uses the following third-party services that may process data:

  • Firebase (Google) — Authentication, Firestore, Cloud Functions, Cloud Storage, App Check, Installations, Analytics
  • DeepSeek — AI test case generation (receives only sanitized prompt text, no personal identifiers)
  • Google AdMob / Unity Ads — Rewarded video advertising (see Ads & Monetization Policy)

7. Your Choices

  • Withhold consent — If you do not check the analytics consent box, you cannot use the app. No analytics data is collected.
  • Delete your account — If you change your mind after consenting, you can delete your account at any time through Account → Delete Account. This removes all server-side data. See Account Deletion for details.
